מה רץ ליד HA ומה רץ בתוכו: Apps ו-HACS

עד עכשיו עבדת רק בתוך HA: אינטגרציות, אוטומציות, דשבורד. היום תתקין לראשונה תוכנה לצד HA, ותראה שכל מה שבנית ב-UI הוא בסוף קבצי YAML על הדיסק. אחר כך נפגוש את HACS, ונחליט מה מותר להכניס לבית של לקוח.

מקור ראשי Apps — home-assistant.io · גישה לקבצים ב-HA OS · תיעוד HACS · Glossary: App, Custom integration.
שינוי שם שחשוב להכיר מה שנקרא פעם Add-ons נקרא היום Apps, והתפריט הוא Settings → Apps (מקור). בפורומים, בסרטונים ובמסמכים שלנו ב-plan-site עוד תפגוש "Add-on". זה אותו דבר.

חימום: מה זכור?

1. לקוח לוחץ על גוף כרטיס ה-Tile של הדוד, ונפתח לו חלון במקום שהדוד יידלק. למה?

ברירת המחדל של גוף הכרטיס היא more-info. רק האייקון עושה toggle.

2. ראית שלמשתמש test_family אין Settings בתפריט הצד. מה מגן כאן על הבית: ה-Visibility או משהו אחר?

משהו אחר: הרשאת המשתמש. ל-test_family אין Administrator. Visibility רק מסתיר כרטיסים ומקטעים מהעין.

3. בנית את script.ask_phone בעורך של HA. איפה הוא שמור לדעתך? (נחש, ובהמשך השיעור תבדוק)

בקובץ scripts.yaml. סקריפטים מהעורך נשמרים שם, וסצנות נשמרות ב-scenes.yaml (מקור, מקור). היום תפתח את הקובץ ותראה.

שלושה סוגי תוספות, שלוש רמות אמון

סוגאיפה רץמי בודק אותובמונחי מפתח
אינטגרציה רשמית בתוך HA צוות HA ספרייה מתוך הספרייה הסטנדרטית
אינטגרציה מותאמת (Custom integration) בתוך HA אף אחד. "על אחריותך", ועלולה לפגוע ביציבות (מקור) חבילת npm של זר, באותו תהליך
אפליקציה (App, לשעבר Add-on) לצד HA, כתוכנה נפרדת תלוי במאגר: רשמי, קהילתי, או צד שלישי בלי שום ערובה (מקור) קונטיינר sidecar, שה-Supervisor מנהל

לפי ההגדרה הרשמית, App היא "חבילת תוכנה עצמאית" שמותקנת על HA OS: למשל MQTT broker, מסד נתונים או שרת קבצים. את רובן מחברים ל-HA דרך אינטגרציה (מקור). כלומר הרבה פעמים יש זוג: האפליקציה היא השרת, והאינטגרציה היא הלקוח שמחבר אותו ל-HA.

מגבלה חשובה: Apps קיימות רק בהתקנה מסוג Home Assistant OS. בשיטות התקנה אחרות מתקינים את אותן תוכנות ידנית (מקור).

HACS עצמו

האפליקציה הראשונה: לראות את ה-YAML

כל מה שבנית ב-UI נשמר בקבצים בתיקייה /config. אפליקציה לעריכת קבצים נותנת לך לראות אותם. יש שתי אפשרויות רשמיות: File editor, קל ופשוט, שבודק תחביר YAML תוך כדי עריכה, ו-Studio Code Server, שהוא VS Code מלא בדפדפן עם טרמינל (מקור). בשביל השיעור מספיק File editor. אם תרצה לעבוד בנוח כמפתח, Studio Code Server מתאים למעבד ARM64 כמו של HA Green.

משימה מעשית · 10 דקות
  1. עבור ל-Settings → Apps → Install app, חפש File editor ולחץ Install.
  2. בלשונית Info לחץ Start ← Open Web UI. אם יש שם האפשרות Show in sidebar, כדאי להפעיל אותה.
  3. פתח את scripts.yaml ומצא את ask_phone. זה ה-YAML שהדבקת בשיעור 6.
  4. פתח את automations.yaml ואת scenes.yaml. מצא את אוטומציית הדוד ואת "Leaving home".
  5. אל תשנה כלום. היום רק קוראים. השאר את האפשרות Enforce basepath דלוקה: היא מגינה מפני שינוי בטעות של קבצים מחוץ ל-/config (מקור).
התובנה שחשוב לזכור ה-UI הוא עורך של קבצי טקסט. סצנה, סקריפט ואוטומציה הם בסוף שורות בקובץ, שאפשר להעתיק, להשוות ולשמור ב-git. זה הבסיס של חלק ב': ה-golden backup כבר מתכנן לנהל YAML ו-Blueprints ב-git.

HACS: חנות הקהילה

HACS (Home Assistant Community Store) הוא אינטגרציה מותאמת שנותנת ממשק לגלות, להוריד ולעדכן רכיבים מהקהילה: אינטגרציות, כרטיסי דשבורד וערכות עיצוב (מקור). במונחי מפתח: מנהל חבילות שמושך קוד ישירות מ-GitHub, בלי ביקורת של צוות HA.

הדרישות מהתיעוד של HACS, בקיצור (מקור):

  • גרסת HA 2024.4.1 ומעלה, בהתקנה נתמכת.
  • גישה לקבצים ולקובץ הלוג. את זה כבר יש לך מהמשימה הקודמת.
  • חיבור אינטרנט יציב, בלי חסימה של GitHub או Cloudflare.
  • חשבון GitHub. ההתחברות נעשית עם קוד חד-פעמי (device code) (מקור).

התיעוד של HACS גם אומר במפורש: אם אתה לא יודע איזה סוג התקנה יש לך, אל תשתמש ב-HACS ולא באף אינטגרציה מותאמת (מקור).

משימה מעשית · 15 דקות · רק בבית שלך
  1. הוסף מאגר אפליקציות: Settings → Apps → Install app ← שלוש נקודות ← Repositories, והדבק https://github.com/hacs/addons (מקור).
  2. באותה חנות בחר Get HACS ← Install ← Start, ופתח את לשונית הלוג. בצע את ההוראות שמופיעות שם.
  3. אתחל את HA (restart).
  4. נקה את המטמון של הדפדפן (או רענון קשיח). בלי זה HACS לא יופיע ברשימה (מקור).
  5. עבור ל-Settings → Devices & services → Add integration, חפש HACS, ואשר את ההצהרות.
  6. העתק את הקוד, היכנס ל-github.com/login/device, הדבק אותו ואשר.
  7. פתח את HACS מתפריט הצד ותסתובב. אל תוריד כלום עדיין.

ההחלטה העסקית: מה נכנס לבית של לקוח?

ב-plan-site יש היום שני כיוונים שמושכים לצדדים שונים:

מסמךמה כתוב שם
Open Home Foundation"כמעט כל התקנה מקצועית של HA משתמשת בזה". שווה לבדוק אם HACS צריך להיות חלק קבוע מצ'ק-ליסט ההתקנה.
PRD 4Watchman ייבנה על Alert המובנה ולא על HACS, כדי "לצמצם תלות בקוד חיצוני שגיא לא כתב ולא שולט בו".

ההמלצה שלי, כנקודת פתיחה לדיון: אצל לקוחות, ברירת המחדל היא רק אינטגרציות רשמיות ואפליקציות מהמאגר הרשמי. כל רכיב מ-HACS נכנס רק אם הוא ברשימת חריגים כתובה, שיש בה למה הוא נחוץ, מי מתחזק אותו ומה התוכנית אם הוא מפסיק להתעדכן. הסיבה: כל רכיב כזה הוא קוד שאף אחד לא בדק, שרץ בתוך HA של הלקוח. כשהוא נשבר בעדכון, אתה זה שמקבל את הטלפון, במסגרת הריטיינר. הבית שלך הוא בדיוק המקום לנסות רכיבים לפני שהם נכנסים לרשימה.

בדיקת זיכרון: תרחישים מהשטח

1. התקנת אצל לקוח את Mosquitto מ-Settings → Apps, והפעלת אותו. אבל אף מכשיר MQTT לא מופיע ב-HA. מה חסר?

האינטגרציה. האפליקציה היא השרת שרץ לצד HA. כדי ש-HA עצמו יראה את המכשירים צריך גם את אינטגרציית MQTT, שמתחברת לשרת. זה הזוג: App + אינטגרציה.

2. לקוח טכני מתעקש להריץ HA ב-Docker על השרת שלו. מה הוא מפסיד מבחינת Apps?

את כל חנות האפליקציות. Apps קיימות רק ב-HA OS, ובהתקנות אחרות צריך להריץ את אותן תוכנות ידנית. זו עוד סיבה לתקנן את כל הלקוחות על HA Green עם HA OS: אותו SOP לכולם.

3. טכנאי שכיר אומר: "התקנתי את HACS דרך Settings → Apps, אז הוא App ואפשר לסמוך עליו". מה לא נכון?

שני דברים. Get HACS היא רק אפליקציה שמורידה את HACS, ו-HACS עצמו הוא אינטגרציה מותאמת. ומה שמגיע דרכו הוא קוד שצוות HA לא בדק. הדרך להתקנה לא אומרת כלום על רמת האמון.

4. אחרי עדכון HA, הבית של לקוח מתחיל להיות איטי ולא יציב. מותקנות אצלו שתי אינטגרציות מ-HACS. מה בודקים ראשון?

את האינטגרציות המותאמות. לפי ההגדרה הרשמית הן לא נבדקות על ידי צוות HA ועלולות לפגוע ביציבות. בודקים בלוג, ומנטרלים אותן אחת אחת. זה בדיוק התסריט שרשימת החריגים נועדה לצמצם.

הניצחון של היום התקנת אפליקציה ראשונה, ראית שכל מה שבנית הוא YAML על הדיסק, ו-HACS מותקן אצלך כמגרש ניסויים. ויש לך שאלה עסקית אמיתית להחליט עליה: מה המדיניות של OneHome לגבי קוד מהקהילה אצל לקוחות.
נתקעת? שאל אם HACS לא מופיע אחרי ה-restart, תדביק לי מה כתוב בלוג של Get HACS. ותספר לי: מה הפתיע אותך ב-scripts.yaml או ב-automations.yaml? ומה דעתך על רשימת החריגים: מסכים, או ש-HACS צריך להיות חלק קבוע מכל התקנה?
