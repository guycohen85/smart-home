הבית שואל: כפתורים בהתראה

עד עכשיו הבית החליט לבד ורק דיווח לך. היום הוא ישאל: "הדוד דלוק ואין אף אחד בבית. לכבות?", ותחת ההודעה יופיעו שני כפתורים. לחיצה בטלפון חוזרת ל-HA, והאוטומציה ממשיכה לפי התשובה. זה רגע הוואו הכי חזק שלך להדגמה עד עכשיו.

מקור ראשי Actionable notifications — companion.home-assistant.io · Script syntax: wait_for_trigger. את המדריך הראשון כדאי לקרוא עד הסוף, כולל הדוגמה עם התריסים. היא הבסיס לכל מה שנבנה כאן.

חימום: מה זכור?

ענה בראש לפני שאתה לוחץ.

1. מה המצב של zone.home כשאתה לבד בבית, ולמה בתנאי כותבים אותו במירכאות?

"1": המצב הוא מספר האנשים שנמצאים ב-zone. במירכאות, כי כל state ב-HA הוא טקסט (שיעור 4).

2. על מה מדלג הכפתור Run actions בעורך האוטומציה?

על הטריגרים ועל התנאים, ומריץ רק את הפעולות. היום זה יתרון: אפשר לבדוק את הכפתורים כשאתה בבית, בלי ש-zone.home יחסום.

שלב 0: להשלים את שיעור 4

כפתורים בהתראה דורשים שהאפליקציה מחוברת ושפעולת notify.mobile_app_* עובדת, אז התרגול משיעור 4 הוא תנאי מקדים. ענית ש-zone.home יהיה 1 בבדיקה א'. זו הייתה תחזית, ועכשיו תבדוק אותה.

משימה מעשית · 15 דקות
  1. לפי תרגול 2 בשיעור 4: התקן את אפליקציית Companion, תן לה הרשאת מיקום Allow all the time, וודא שהטלפון מסומן ב-Track device של ה-person שלך.
  2. ב-Developer tools → Actions מצא את שם הפעולה notify.mobile_app_<הטלפון>, ושלח ממנה הודעת ניסיון. הגיעה? אפשר להמשיך.
  3. באוטומציה הדוד נשאר דלוק (בדיקה) הוסף את התנאי zone.home = 0 ושמור.
  4. בדיקה א': הדלק את המכשיר, חכה דקה, פתח Traces ולחץ על צומת התנאי. האם התחזית שלך נכונה?

איך לחיצה בטלפון חוזרת לבית

ההתראה היא לא חלון שיחה. היא הודעה חד-כיוונית, והלחיצה חוזרת ל-HA בנפרד, כ-event. האוטומציה צריכה לחכות לו:

שולחים notify + actions

ההתראה נשלחת עם רשימת כפתורים. לכל כפתור יש title (מה רואים) ו-action (מזהה שחוזר ל-HA).

לוחצים event

האפליקציה יורה ב-HA את האירוע mobile_app_notification_action, ובתוכו המזהה של הכפתור.

מחכים wait_for_trigger

האוטומציה עוצרת באמצע ומחכה לאירוע הזה, עם תקרת זמן (timeout).

מחליטים if / then

המשתנה wait.trigger מראה על איזה כפתור לחצו. אם הזמן נגמר, הוא none.

המבנה של האירוע והשם שלו לקוחים מהתיעוד של האפליקציה, ו-wait.trigger מתיעוד ה-Script. זה אותו טריגר שאתה מכיר משיעור 3, רק שהפעם הוא נמצא בתוך הפעולות: טריגר שני, באמצע ריצה.

למה המזהה כולל את context.id

האירוע של הלחיצה משותף לכל ההתראות בבית. אם גם אוטומציית מכונת הכביסה תשתמש בכפתור OFF, לחיצה אחת תעיר את שתיהן. התיעוד ממליץ לבנות מזהה ייחודי לכל ריצה, מתוך context.id שלה. ככה כל כפתור שייך בדיוק לריצה ששלחה אותו (מקור).

התובנה שחשוב לזכור ה-timeout הוא לא פרט טכני, הוא החלטה על הלקוח. מה הבית עושה כשאף אחד לא עונה? אצלך, כיבוי הוא ברירת מחדל טובה. אצל משפחה עם סבתא בלי סמארטפון (שיעור 4), אולי עדיף להשאיר דלוק. זו שאלה לשאול ב-Onboarding, לא לנחש.

תרגול 2: לכתוב את זה ב-YAML

עד עכשיו בנית ב-UI וקראת את ה-YAML. את הכפתורים הכי נוח לכתוב ישר ב-YAML, כי הם יושבים בתוך שדה data מקונן. כמפתח, זה המקום שלך.

משימה מעשית · 15 דקות
  1. פתח את האוטומציה ← שלוש נקודות ← Edit in YAML.
  2. החלף את כל החלק של actions: בזה שלמטה. שנה את pixel_8 לשם הטלפון שלך (בשני המקומות), ואת switch.boiler למכשיר שלך.
  3. לבדיקה, שנה את ה-timeout ל-minutes: 1. אחר כך תחזיר ל-10.
  4. שמור, וחזור למצב העריכה הוויזואלי. שים לב איך ה-UI מציג את ה-wait ואת ה-if: אותה אוטומציה, שתי תצוגות.
actions:
  - variables:
      action_off: "{{ 'BOILER_OFF_' ~ context.id }}"
      action_keep: "{{ 'BOILER_KEEP_' ~ context.id }}"
  - action: notify.mobile_app_pixel_8
    data:
      message: הדוד דלוק ואין אף אחד בבית. לכבות?
      data:
        actions:                 # אנדרואיד: עד 3 כפתורים
          - action: "{{ action_off }}"
            title: כבה
          - action: "{{ action_keep }}"
            title: השאר דלוק
  - wait_for_trigger:
      - trigger: event
        event_type: mobile_app_notification_action
        event_data:
          action: "{{ action_off }}"
        id: "off"                # במירכאות! off בלי מירכאות הופך ל-false
      - trigger: event
        event_type: mobile_app_notification_action
        event_data:
          action: "{{ action_keep }}"
        id: keep
    timeout:
      minutes: 10
  - if:
      - condition: template
        value_template: "{{ wait.trigger is none or wait.trigger.id == 'off' }}"
    then:
      - action: switch.turn_off
        target:
          entity_id: switch.boiler
      - action: notify.mobile_app_pixel_8
        data:
          message: כיביתי את הדוד.

שתי הערות מפתח למפתח: data מופיע פעמיים, החיצוני שייך לפעולה והפנימי לאפליקציה. ו-"off" במירכאות, כי ב-YAML המילים on/off בלי מירכאות הופכות לבוליאני. זו אותה סיבה שכותבים to: "on" בטריגר (מקור).

תרגול 3: לבדוק את שלושת המסלולים

משימה מעשית · 10 דקות

בכל בדיקה: הדלק את המכשיר, ואז בעורך האוטומציה ← שלוש נקודות ← Run actions. ההתראה אמורה להגיע תוך שניות, גם כשאתה בבית.

  1. "כבה": לחץ על הכפתור. המכשיר כבה, ומגיעה הודעת "כיביתי את הדוד".
  2. "השאר דלוק": המכשיר נשאר דלוק, ולא מגיעה הודעה נוספת.
  3. בלי תשובה: אל תיגע בטלפון. אחרי דקה המכשיר כבה לבד.
  4. פתח את ה-Trace של אחת הריצות ולחץ על צומת ה-wait. תראה שם את הטריגר שהעיר אותו, או שהזמן נגמר.
  5. החזר את ה-timeout ל-10 דקות ושמור.

לא מופיעים כפתורים? באנדרואיד צריך למשוך את ההתראה למטה כדי לראות אותם. באייפון, לחיצה ארוכה על ההתראה.

בדיקת זיכרון: תרחישים מהשטח

1. אצל לקוח, ההתראה נשלחת לשני ההורים. אמא לוחצת "השאר דלוק", ושתי דקות אחר כך אבא לוחץ "כבה". מה קורה, ולמה?

הדוד נשאר דלוק. הלחיצה של אמא סיימה את ה-wait, והריצה הסתיימה. כשאבא לחץ, אף אחד כבר לא הקשיב. בשביל זוג הורים כדאי לשלוח אחרי התשובה הודעה לשניהם ("אמא השאירה את הדוד דלוק"), כדי שאף אחד לא יחשוב שהוא כיבה.

2. לקוח אומר "לחצתי על הכפתור ולא קרה כלום". איפה אתה רואה אם הלחיצה בכלל הגיעה ל-HA?

ב-Developer tools → Events: מאזינים ל-mobile_app_notification_action ומבקשים מהלקוח ללחוץ שוב (מקור). אם האירוע מגיע, הבעיה אצלך: המזהה לא תואם, או שהריצה כבר לא מחכה (כמו ההתראה של אתמול בתרגול 1). אם הוא לא מגיע, הבעיה בטלפון או בחיבור שלו ל-HA.

3. למה לא לשלוח את ההתראה עם כפתור "כבה" ישר מהטריגר, בלי תנאי הנוכחות?

כי הלקוח יקבל שאלה בכל פעם שהוא מדליק את הדוד בבית, וזה יתיש אותו מהר. התנאי מסנן את המקרים שבהם השאלה באמת מועילה. התראה טובה היא נדירה: היא מגיעה רק כשיש לה משהו חשוב להגיד.

הניצחון של היום הבית שלך שואל שאלה, מקבל תשובה מהכיס, ופועל לפיה, עם ברירת מחדל בטוחה כשאין תשובה. בהדגמה ללקוח: אתה מדליק את הדוד, מראה לו את הטלפון, והוא לוחץ בעצמו "כבה". זה עובד מקומית, והלחיצה עוברת דרך השרת בבית שלו.
נתקעת? שאל אם הכפתורים לא מופיעים, או שהלחיצה לא מעירה את ה-wait, תדביק לי את ה-YAML ואת ה-Trace (או את מה שראית ב-Events). ותספר לי: מה ראית בצומת התנאי בבדיקה א' של שלב 0, והאם התחזית שלך הייתה נכונה?
